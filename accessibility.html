Accessibility Considerations

This page describes how I've built and plan to keep building accessibility into Tick by Tick, so the site works for people using screen readers, keyboard-only navigation, low vision, or color blindness.

Semantic structure and headings

The site uses semantic HTML elements (header, nav, main, section, footer) instead of generic divs, so assistive technology can identify the page regions correctly. Headings follow a logical order (one h1 per page, h2 for major sections), so screen reader users can navigate by heading level instead of reading the whole page top to bottom. The navigation menu has an aria-label so it's announced clearly, and the current page link uses aria-current so users know where they are.

Color and contrast

Text and background colors meet WCAG AA contrast requirements (at least 4.5:1 for normal text) in both light and dark mode, which the site supports automatically based on the visitor's system setting. Color is never used as the only way to convey meaning; for example, gains and losses in the calculator are shown with both a color change and a plus or minus sign in the text, so a colorblind user isn't relying on green versus red alone.

Keyboard access and focus

Every interactive element (links, the calculator's dropdowns and number fields, the glossary's expandable details) is reachable and operable using only the Tab and Enter keys, with no mouse required. A visible focus outline appears on whatever element is currently selected, so keyboard users always know where they are on the page.

Forms and labels

Every form control in the profit and loss calculator has a real, visible <label> element tied to it with a matching "for" and "id" attribute, rather than placeholder text alone, so screen readers announce what each field is for. The calculator's result area uses aria-live so a screen reader automatically reads the updated profit or loss after the visitor changes an input, without requiring them to move focus manually.

Images and non-text content

Any image added to the site going forward will include descriptive alt text, and purely decorative images will use empty alt attributes so screen readers skip them instead of reading a meaningless filename.

Testing plan

Before publishing updates, I plan to check the site with the browser's built-in accessibility inspector, a contrast checker, and by tabbing through the whole page without a mouse to confirm every control is reachable in a sensible order.
